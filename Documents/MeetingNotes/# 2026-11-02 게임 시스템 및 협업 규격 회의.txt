# 2026-11-02 게임 시스템 및 협업 규격 회의

## 1. 회의 목적
플레이어 및 적 시스템의 기본 데이터 구조와 공격 판정 방식, 기획 데이터 관리 방법 및 Git Branch 분담 논의

## 2. 논의 내용

### 플레이어 시스템
- 체력은 정수형으로 관리하며, 체력 수치보다는 목숨의 개수를 기준으로 플레이하는 방식 검토
- 피격 시 플레이어 대신 무기가 피해를 받는 디코이 시스템 구상
  - 피격 시 무기 단계가 하락하는 방식 검토
- 공격력은 정수형으로 관리
- 이동속도 데이터 관리
- 폭탄 보유 개수는 정수형으로 관리

### 적 시스템
- 체력은 정수형으로 관리
- 공격력은 플레이어의 목숨을 1개 감소시키는 방식으로 구상
- 이동속도 데이터 관리

### 플레이어 → 적 공격 판정
- `IDamageable` 인터페이스를 활용한 피해 처리 방식 검토
  ```csharp
  public interface IDamageable
  {
      void TakeDamage(int damage);
  }
  ```
- 탄막 생성 시 공격력을 저장하고, 적과 충돌하면 저장된 공격력을 기반으로 피격 처리

### 적 → 플레이어 공격 판정
- 적의 Tag를 `Enemy`로 설정하는 방식 검토
- 플레이어가 `Enemy` Tag를 가진 오브젝트와 충돌하면 피격 처리

### 기획 데이터 저장 방식
- ScriptableObject(SO)와 내부변수를 구분하여 관리하는 방향 논의

1. **ScriptableObject**
   - 플레이어: 공격력, 이동속도
   - 적: 이동속도

2. **내부변수**
   - 플레이어: 목숨, 폭탄 보유 개수
   - 적: 현재 체력
   - 공통: 점수

### 적 공격 패턴
- 단일 적의 탄막 공격 방식 검토
  1. 아래 방향으로 직선 발사
  2. 플레이어 위치를 추적하는 유도 공격
- 적 편대 공격 방식 검토
  1. 편대가 공격 위치까지 이동한 후 순차적으로 공격하는 방식

### Git Branch 분담
- `Player`: 플레이어 시스템 담당
- `Enemy`: 적 및 적 공격 시스템 담당
- `Manager`: GameManager 및 UI 담당

## 3. 현재까지의 잠정 방향
- 플레이어와 적의 체력은 정수형으로 관리
- 플레이어는 목숨 개수 기반의 체력 시스템을 사용
- 플레이어의 적 공격은 `IDamageable` 인터페이스를 통한 피해 처리 방식 검토
- 적의 플레이어 공격은 Tag 기반 충돌 판정 방식 검토
- 기획 데이터는 SO, 플레이 도중 변경되는 데이터는 내부변수로 분리하여 관리
- Git Branch는 Player, Enemy, Manager 단위로 구분

## 4. 미확정 사항
